AI Engineering Roadmap
8-week master plan
Plan
Reviewed and updated for May 2026 · 8-week intensive track
8-week sprint: 60 hours of structured material × 2 = 120 hours total (learning + implementation), which is about 15 hours per week. Treat it like a part-time job and put it on your calendar.
4
Phases
8 weeks
Intensive duration
12
Phase exercises
Do the exercises during the phase, immediately after the related topic cluster, not all at the end. Each one should become a small public artifact: push the code to GitHub, write a concise README with screenshots or a demo clip, and share what you built on LinkedIn or YouTube.
Phase 1 — Foundations · week 1–2
Python fluency
numpy, pandas, async/await, plus pydantic — typed models are now central to AI codebases.
Exercise 1.1 · Build and publish
Learning Progress Data Explorer
Build a Python CLI or tiny web app that reads CSV/JSON learning logs, cleans them with pandas, calculates weekly progress, and exports one chart plus a Markdown summary.
When: Do this right after Python fluency, pandas/numpy, and basic project setup.
Solidifies: Python fluency, pandas, numpy basics, file I/O, plotting, data cleaning, project structure, README writing.
Public artifact: Push the repo with sample data, screenshots, and a LinkedIn post or short YouTube walkthrough of the progress dashboard.
Just-enough math
Linear algebra intuition and basic probability — enough to read papers, not derive them.
Core ML concepts
Training vs inference, loss, overfitting, embeddings, tokens — enough to reason about model behavior.
Exercise 1.2 · Build and publish
Embedding Similarity Playground
Create a local notebook or Streamlit app where you embed your notes, visualize nearest neighbors, and explain why semantically similar text clusters together.
When: Do this after just-enough math, core ML concepts, tokens, and embeddings.
Solidifies: embeddings, vectors, cosine similarity, tokens, linear algebra intuition, data visualization, model behavior.
Public artifact: Push the notebook/app and share a post explaining embeddings with one visual example from your own notes.
Transformer architecture intuition
Attention, residual streams, how next-token prediction creates apparent reasoning.
LLM behavior fundamentals
new
Reasoning models vs base models, context windows, tool use, why models hallucinate. Foundational for everything after.
Exercise 1.3 · Build and publish
Typed LLM Behavior Lab
Build a small Python app that sends controlled prompts to an LLM, records outputs into Pydantic models, and compares temperature, instruction clarity, and context length.
When: Do this at the end of Phase 1, after transformer intuition and LLM behavior fundamentals.
Solidifies: pydantic, API calling, experiment design, LLM behavior, hallucination patterns, structured result capture.
Public artifact: Push the experiment runner and post your findings as "3 things I learned about LLM behavior."
Phase 2 — LLM engineering · week 3–4
Context engineering
updated
The 2025 successor to "prompt engineering" — composing system prompts, examples, retrieved data, and tool results into context that fits and works.
LLM APIs — OpenAI, Anthropic, Gemini
updated
Structured outputs, function calling, prompt caching, streaming, batch APIs. Know the cost and latency tradeoffs of each provider.
RAG — retrieval, hybrid search, reranking, agentic RAG
updated
Vector + BM25 hybrid, cross-encoder rerankers, query rewriting, and letting the agent decide when to retrieve. Long context complements but doesn't replace.
Exercise 2.1 · Build and publish
RAG Knowledge Base for Your Own Docs
Build a Q&A app over your notes, PDFs, or code snippets with chunking, embeddings, retrieval, answer citations, and a small comparison between naive retrieval and improved retrieval.
When: Do this after context engineering, LLM APIs, structured outputs, and the RAG topic.
Solidifies: RAG, chunking, embeddings, vector search, retrieval quality, citations, context construction, error analysis.
Public artifact: Push the repo with a demo dataset, screenshots, and a LinkedIn/YouTube explanation of where retrieval failed and how you improved it.
Multimodal — vision and audio inputs
new
Pass images, PDFs, screenshots, audio to modern models. Now table stakes — most production AI products use vision somewhere.
Exercise 2.2 · Build and publish
Multimodal Document Analyst
Build an app that accepts a screenshot, invoice, resume, or report page, extracts structured data, validates it with Pydantic, and lets the user ask follow-up questions.
When: Do this after multimodal inputs and structured output/schema validation.
Solidifies: vision inputs, PDF/screenshot handling, structured outputs, schema design, validation, prompt/context design.
Public artifact: Push the repo with redacted examples and post a before/after demo showing unstructured input becoming usable structured data.
Modern orchestration — LangGraph, Pydantic AI, DSPy
updated
LangGraph for stateful graphs, Pydantic AI for typed agents, DSPy for programmatic prompt optimization. LangChain itself is now legacy for new code.
Vercel AI SDK
new
Your unfair advantage as a frontend engineer — streaming, tool use, generative UI in React/Next.js. Ship AI features your team can actually merge.
Exercise 2.3 · Build and publish
Streaming AI Copilot in React
Build a Next.js or React copilot with streamed responses, one tool call, loading states, retry behavior, and a clean UI that feels production ready.
When: Do this after orchestration and Vercel AI SDK streaming/tool-use patterns.
Solidifies: Vercel AI SDK patterns, streaming, tool calling, frontend state, latency UX, provider cost/latency tradeoffs.
Public artifact: Push the repo, deploy it, and share a demo clip focused on the UX decisions that make AI feel responsive.
Fine-tuning, RAG, and prompting
Decision framework and hands-on. LoRA, instruction tuning, and the OpenAI / Anthropic fine-tuning APIs — know enough to actually do it, then choose wisely.
Phase 3 — Agentic AI · week 5–6
AI agents and tool use
Tool/function calling loops, planning, memory, when an agent is the right shape vs a workflow.
Exercise 3.1 · Build and publish
Tool-Using Research Agent
Build an agent that can search local docs, call at least two tools, produce a cited brief, and show the tool steps it took before answering.
When: Do this after agent basics, tool/function calling, planning, and memory.
Solidifies: tool calling, planning loops, memory, agent vs workflow judgment, traceable outputs, failure handling.
Public artifact: Push the repo and share a demo where you intentionally show one failed tool path and how the agent recovers.
MCP — Model Context Protocol
updated
Now an industry standard supported by OpenAI, Anthropic, Google, JetBrains, Cursor. Build at least one server and one client.
Exercise 3.2 · Build and publish
Tiny MCP Server and Client
Build an MCP server exposing a useful personal tool, such as reading a learning log, querying a bookmarks file, or creating a GitHub issue, and connect it to a simple client.
When: Do this immediately after the MCP topic, before going deep into multi-agent systems.
Solidifies: MCP primitives, server/client boundaries, tool schemas, typed inputs, integration testing, AI app extensibility.
Public artifact: Push both server and client with a setup video or README GIF showing another developer how to run it.
Multi-agent systems
Supervisor patterns, handoffs, when to use them and when one good agent beats five mediocre ones.
Computer use and browser agents
new
Anthropic Computer Use, OpenAI Operator-style agents, Playwright-driven flows. The next big surface for AI products.
Voice AI and realtime APIs
new
Speech-to-speech models and WebRTC streaming. Voice agents are now a real product category, not a demo.
Evals — the highest-leverage skill
updated
Error analysis, custom datasets, LLM-as-judge with calibration, regression testing. The single skill that distinguishes serious AI engineers from prompt tinkerers.
Exercise 3.3 · Build and publish
Agent Eval Harness
Create a 20-row evaluation set for your agent, run it on every change, score answer quality with a rubric, and log the biggest failure modes.
When: Start the eval rows while building Exercises 3.1 and 3.2, then finish this after the evals topic.
Solidifies: eval datasets, LLM-as-judge calibration, regression testing, error analysis, measurable agent improvement.
Public artifact: Push the eval harness and post the scorecard showing what improved between version 1 and version 2.
Phase 4 — Production and MLOps · week 7–8
Deployment — FastAPI, Docker, Modal
updated
FastAPI for the API layer, containers for portability, Modal or similar for serverless GPU when you need fine-tuning or open models.
Exercise 4.1 · Build and publish
Production API Wrapper for Your AI App
Turn one earlier project into a FastAPI service with Docker, typed request/response models, health checks, rate limiting, and a simple deploy target.
When: Do this after deployment, FastAPI, Docker, and environment/config basics.
Solidifies: FastAPI, Docker, deployment, API design, environment config, pydantic contracts, operational readiness.
Public artifact: Push the productionized repo and share an architecture diagram plus a short deployment walkthrough.
Observability — Langfuse, Logfire, Arize
updated
Trace every LLM call. OpenTelemetry-based tooling has matured; pick one and instrument from day one.
Security — prompt injection, jailbreaks, OWASP LLM Top 10
updated
Indirect prompt injection is the most common AI vulnerability shipped to production. Know the patterns and the OWASP LLM Top 10.
Exercise 4.3 · Build and publish
Prompt-Injection Defense Lab
Add adversarial test cases to your RAG or agent app, detect risky instructions, isolate retrieved content from system instructions, and document what still breaks.
When: Do this immediately after security, OWASP LLM risks, and production hardening.
Solidifies: OWASP LLM risks, indirect prompt injection, security testing, trust boundaries, eval-driven mitigation, incident notes.
Public artifact: Push the test suite and share a security write-up with safe examples of attacks, mitigations, and remaining risks.
Cost and latency optimization
new
Prompt caching, model routing (small first, escalate to large), request batching, quantization, and self-hosted inference (vLLM / SGLang). The 5–10x lever in production.
Exercise 4.2 · Build and publish
Observability and Cost Dashboard
Instrument your LLM calls with traces, latency, token usage, error labels, and per-feature cost. Add a dashboard or exported report that explains what changed after optimization.
When: Do this after observability, tracing, cost, and latency optimization topics.
Solidifies: Langfuse/Logfire-style tracing, observability, token accounting, latency analysis, prompt caching, model routing, cost control.
Public artifact: Push the instrumentation and post a case study: "How I reduced latency/cost in my AI app."
Skills to skip
Training LLMs from scratch Classic ML deep dives (SVMs, decision trees) TensorFlow / Keras Hadoop / Spark Computer vision removed — now multimodal

Execution playbook
Tricks to finish ASAP
Skim, don't read. Most docs are reference material. Read at 2x scan first; deep-dive only when you hit something you'll actually use this week.
Watch videos at 1.5×–2×. Karpathy's Z2H goes from ~7 hr to ~4 hr at 1.75×. You will not lose information; you will gain time.
Build before you finish learning. Pick one project on day 3 — "a Vercel AI SDK + LangGraph + MCP RAG-and-agent thing" — and treat the curriculum as just-in-time learning.
Skip what you already know. As a frontend engineer: skim Learn X in Y, Async IO, FastAPI, Docker. Don't rewatch the basics.
Compound projects, don't restart them. Same repo for everything: add multimodal → add agents → add MCP → add evals → add Logfire → add caching. One repo at the end shows depth.
Phase 4 is JIT. Don't learn FastAPI, Docker, Modal, vLLM, OWASP until you have something that actually needs them. They're 1-day skills when motivated.
Use AI to learn AI. Paste any confusing concept into Claude or ChatGPT and ask "explain like I'm a frontend engineer." It is the world's best on-demand tutor.
Public artifacts beat private notes. Tweet weekly. One LinkedIn post per phase. A 20-line README on each project. Recruiters at top AI companies read these.
Find one accountability partner. Latent Space Discord, AI Engineer community, a friend doing the same. Solo timelines usually drift; paired timelines usually ship.
Stop watching what you already know. If a video says "tokens are sub-words" and you already know that, jump 3 minutes.
Two non-negotiable evals. Even on a tiny demo, write a 20-row eval set + a Langfuse trace. That single habit is what separates the top decile from the rest of the field.
Execution order that works. Hit Phase 1 + Phase 2 hard for 4 weeks → ship a public project → then layer Phase 3 + Phase 4 onto that same project for 4 more weeks. Two months from today you'd have a portfolio piece and a credible AI-engineer narrative.
